# Experiment 03 raw evidence — 2026-08-25

## Scope

Question: on one CPU thread, how much slower is column-major traversal than
row-major traversal when both process the same large row-major matrix and
perform the same arithmetic once per element?

The pre-recorded prediction was an approximately `8x` column-major slowdown.
Less than `2x` would make the locality model incomplete; more than `16x` would
mean cache-line utilization alone was insufficient to explain the result.

## Manipulation check before timing

The runner confirmed that GCC did not report any source loop as vectorized.
The benchmark then observed:

```text
METADATA,observed_cache_line_bytes,64
METADATA,row_bytes,64
METADATA,row_inner_stride_bytes,4
METADATA,column_inner_stride_bytes,64
METADATA,buffer_alignment_remainders,0:0:0
METADATA,openmp_threads,1
```

Each aligned logical row was exactly one observed cache line. Row-major inner
iterations addressed adjacent four-byte floats; column-major inner iterations
addressed values one 64-byte row apart. Vectorization, loop interchange, and
multi-core execution remained fixed out of the comparison.

## Observation versus interpretation

Observed:

- Manipulation and correctness checks passed before timing.
- The row-major and column-major inner strides were four and 64 bytes.
- The 64 MB matrix was larger than the 35.8 MiB shared L3 cache.
- Column-major traversal was `12.815x` slower than row-major traversal.
- The slowdown was larger than the `8x` prediction but remained between the
  pre-recorded `2x` and `16x` thresholds.

Interpretation consistent with, but not proved by, those observations:

- Row-major traversal used all sixteen floats in a logical cache-line-sized row
  before moving on.
- Column-major traversal made sixteen passes over a larger-than-cache matrix,
  increasing the reuse distance and likely increasing cache-line movement.
- Cache capacity, hardware prefetching, TLB behavior, cache conflicts, and
  store allocation or writeback may all contribute to the exact ratio.
- No hardware counters were collected, so the result does not attribute the
  slowdown to a specific cache level or mechanism.

The result did not cross either falsification threshold, so no counter or
working-set follow-up was added to the baseline experiment.
