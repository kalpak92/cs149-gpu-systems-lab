## First correctness criterion: failed

The first run compared the CPU and CUDA `float32` results with `rtol=1e-4`
and `atol=1e-5`.

Here, `rtol` is the **relative tolerance** and `atol` is the **absolute
tolerance**. For each result element, PyTorch accepts the CUDA value as close
to the CPU reference when:

```text
|CUDA result - CPU reference| <= atol + rtol * |CPU reference|
```

With `rtol=1e-4`, the allowed difference includes 0.01% of the reference
value's magnitude. With `atol=1e-5`, it also includes a fixed allowance of
0.00001 regardless of magnitude. The absolute tolerance matters most when the
reference value is near zero, because the relative part then contributes
almost nothing. This is why a comparison can fail near zero even when the
overall CPU and CUDA errors are of the same order.

```bash
/home/ubuntu/venvs/torch-gpu/bin/python experiments/00_machine-baseline/first_cuda_workload.py
```

```text
AssertionError: Tensor-likes are not close!

Mismatched elements: 10 / 262144 (0.0%)
Greatest absolute difference: 2.5797635316848755e-05 at index (148, 279) (up to 1e-05 allowed)
Greatest relative difference: 0.0027929809875786304 at index (374, 230) (up to 0.0001 allowed)
```

This failure was preserved rather than silently loosening the tolerance.
